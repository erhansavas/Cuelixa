# Cuelixa Software Audit and Remediation Report

Audit branch: `astra-audit-fixes`
Baseline: `main` at `68415831e39b0f0787cc1d8b47d7891148d4a58c`
Audit date: 2026-09-05
Follow-up completed: 2026-09-08

## Project summary

Cuelixa is a native, local-first macOS listening-practice application. Its documented purpose is to play lesson audio from the user's local library, resume and track listening progress, display synchronized on-device subtitles in a compact floating overlay, and optionally produce local Speech-framework transcripts. It has no account service, backend, analytics, telemetry, updater, bundled runtime, or third-party package-manager dependency.

The verified implementation is Swift 6 mode in an Xcode project using SwiftUI/AppKit, AVFoundation, Speech, MediaPlayer, Foundation, Combine, OSLog, CryptoKit, CoreServices/FSEvents, UniformTypeIdentifiers, Carbon.HIToolbox, Darwin, and system SQLite3. The app and test targets set `MACOSX_DEPLOYMENT_TARGET = 26.0`, target arm64, enable complete strict concurrency and warnings-as-errors, and enable Hardened Runtime. The project records marketing version `0.6.66` and build `52`. README qualification records Xcode 26.6 (17F113) and Swift 6.3.3; the repository does not vendor the compiler or SDK.

At audit start, the repository contained 39 commits across the inspected refs and ten historical pull requests (all historical entries are pull requests; no standalone issues); no review threads required an unresolved decision. This audit is delivered in draft PR #11. PR #3 intentionally restored the prior qualified icon/raster baseline; PR #5 introduced the importer, scanner, Speech executor boundary, and hardening tests; PR #6 intentionally allows either foreground or background launch for the nonactivating overlay. The current open Dependabot PR #10 proposes the same `actions/attest` patch included below.

Baseline empirical evidence available in GitHub Actions is run [32741911775](https://github.com/erhansavas/Cuelixa/actions/runs/32741911775): macOS 26.5.2, Xcode 26.6 (17F113), Swift 6.3.3, Debug/Release build, Analyze, 19 Swift Testing tests, two XCTest performance tests, and one UI launch test passed. The release run [32742772157](https://github.com/erhansavas/Cuelixa/actions/runs/32742772157) also passed source-manifest, build, ad-hoc signing/Hardened Runtime, DMG, checksum, attestation, and publication gates. Those runs establish the baseline only; they do not establish exact macOS 26.6.2 execution or macOS 27 execution.

Initial remediation branch CI run [33961431631](https://github.com/erhansavas/Cuelixa/actions/runs/33961431631) completed successfully on the arm64 `macos-26` runner: the log records macOS 26.6.2 (25G83), Xcode 26.6 (17F113), Swift 6.3.3, and the MacOSX26.5 SDK. The source manifest, smoke checks, 22 Swift Testing tests, two XCTest performance tests, one UI launch test, Debug/Release builds, and Analyze all passed. The validator intentionally skips its generated local AVPlayer runtime smoke in CI compatibility mode. That run predates the additional hardening below and is not evidence for the final source tree.

## Follow-up verified findings and remediation

The macOS 27 host made the earlier unconfirmed input and filesystem cases reproducible. The follow-up preserves the native architecture, minimum macOS 26 target, existing library selection, and deliberate direct-distribution security model.

| Finding | Evidence and outcome | Remediation |
|---|---|---|
| Unbounded and special-file subtitle reads | A FIFO could block reading; oversized sidecars were allocated without a budget. Repeated unmatched ampersands took over seven seconds in a baseline probe. | `LocalFileAccess` opens nonblocking, checks the opened descriptor for a regular file, and bounds/cancels reads. SRT input is limited to 16 MiB; entity lookup scans a fixed-size window. User-owned links to regular sidecars remain supported. |
| Excessive subtitle layout work and numeric traps | Baseline balancing of 2,000 words took about 3.4 seconds; 20,000 words exceeded the probe timeout. Extreme finite times trapped integer conversion. | Normal cues retain the existing scoring with precomputed word lengths/flags. Long cues use a linear partition preserving every word. Formatting, SRT encoding, and transcription progress reject or safely bound invalid numbers. |
| Transcript traversal, reset ownership, and stale verification | Baseline commit accepted `../outside`; reset removed unrelated notes; a linked SRT could remain memoized after its target changed. | Require 64-character lowercase SHA-256 keys; reject links for managed reads; bound manifests; verify the exact bytes read and recheck signatures. Serialize reset/publication/verification. Reset unlinks only owned regular transcript/manifest names and preserves unrelated files, directories, and links. |
| Transcript publication follows unsafe destination assumptions | Publication must replace final entries without writing through links or certifying bytes replaced after publication. | Stage beside the destination, publish via atomic `rename`, and hash the encoded bytes. The regression test verifies external SRT and manifest link targets remain unchanged. Reuse the common cancellable hasher instead of a second copy. |
| Managed-directory and database boundaries | Managed paths could be substituted with links; SQLite link rejection initially also rejected the system `/var` ancestor alias. Corrupt databases must remain available for recovery. | Validate owned directories through no-follow descriptors and set mode 0700 without changing source-library permissions. Canonicalize the validated database parent with `realpath`, retaining no-follow protection on the database filename. Corrupt/link targets are not overwritten. |
| Startup cleanup races active imports | Cleanup and imports can overlap, including across app instances. Prefix-only recursive cleanup could delete unrelated directories. | Hold shared filesystem leases for imports and a nonblocking exclusive lease for cleanup. Remove only regular `.cuelixa-import-<UUID>.tmp` entries; retry cleanup after an active import. Reject non-file import URLs. |
| Unicode and literal search | SQLite's original `LOWER/LIKE` route did not match non-ASCII case correctly and interpreted `%` and `_` as wildcards. | Use Foundation's localized standard matching for titles after section selection. Tests cover accents, Cyrillic, literal wildcard characters, database reopening, resume state, and rename/completion persistence. |
| macOS 27 SDK warnings and source validation | The macOS 27 SDK deprecates the old AVPlayerItem notification spellings; Xcode user-state files caused source-pattern false positives. | Use the current notification properties; scan shipping project configuration and shared schemes rather than machine-local workspace state. The Icon Composer document explicitly targets macOS. |

`SecurityRegressionTests.swift` adds 15 tests for these boundaries. They supplement the existing importer/scanner/database/transcription and performance suites. These controls limit accidental and hostile local-file inputs; they do not claim isolation from a malicious process with the same user identity.

No Critical or High application defect survived the verification and falsification process. No credential or API-key hit was found in the 39-commit text/blob scan, but GitHub’s repository Security, Dependabot, and code-scanning views were not exposed by the configured connector; that absence is not a clearance claim.

## Rejected ideas

- Enabling App Sandbox, adding notarization, or removing legacy `~/podcast` support: the repository documents these as deliberate distribution/migration decisions; no new defect evidence justifies the added entitlement/bookmark architecture or paid signing dependency.
- Treating the legacy raster icon as intrinsically broken: Apple documents automatic adaptation and permits flattened icons. Actual border/visibility failure cannot be claimed without native rendering.
- Restoring the foreground-only launch assertion: PR #6 and the existing UI behavior establish that the nonactivating overlay can leave the process in the background by design.
- A broad subtitle rewrite remains unnecessary. The follow-up measurements justified bounded input handling and a narrow long-cue partition while retaining ordinary subtitle scoring and all words.
- Fixing the periodic playback observer’s possible post-await generation race: static review did not produce a deterministic stale-session outcome, and the other callback paths already guard their generation; it remains unverified.
- Broad dead-code/dependency cleanup: duplicate helpers and compatibility entry points were not shown to cause a defect and removal would expand scope without measurable user value.
- Calling the `actions/attest` advisory a High Cuelixa vulnerability: the exact workflow input and bundled `nobrace` path falsify exploitability for the reviewed release route; the finding is Low supply-chain hygiene.
