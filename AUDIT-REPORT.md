## Project summary

Cuelixa is a native, local-first macOS listening-practice application. Its documented purpose is to play lesson audio from the user's local library, resume and track listening progress, display synchronized on-device subtitles in a compact floating overlay, and optionally produce local Speech-framework transcripts. It has no account service, backend, analytics, telemetry, updater, bundled runtime, or third-party package-manager dependency.

The verified implementation is Swift 6 mode in an Xcode project using SwiftUI/AppKit, AVFoundation, Speech, MediaPlayer, Foundation, Combine, OSLog, CryptoKit, CoreServices/FSEvents, UniformTypeIdentifiers, Carbon.HIToolbox, Darwin, and system SQLite3. The app and test targets set `MACOSX_DEPLOYMENT_TARGET = 26.0`, target arm64, enable complete strict concurrency and warnings-as-errors, and enable Hardened Runtime. The project records marketing version `0.6.66` and build `52`. README qualification records Xcode 26.6 (17F113) and Swift 6.3.3; the repository does not vendor the compiler or SDK.

The repository contains 39 commits across the inspected refs, ten pull requests (all historical entries are pull requests; no standalone issues), and no review threads requiring an unresolved decision. PR #3 intentionally restored the prior qualified icon/raster baseline; PR #5 introduced the importer, scanner, Speech executor boundary, and hardening tests; PR #6 intentionally allows either foreground or background launch for the nonactivating overlay. The current open Dependabot PR #10 proposes the same `actions/attest` patch included below.

Baseline empirical evidence available in GitHub Actions is run [32741911775](https://github.com/erhansavas/Cuelixa/actions/runs/32741911775): macOS 26.5.2, Xcode 26.6 (17F113), Swift 6.3.3, Debug/Release build, Analyze, 19 Swift Testing tests, two XCTest performance tests, and one UI launch test passed. The release run [32742772157](https://github.com/erhansavas/Cuelixa/actions/runs/32742772157) also passed source-manifest, build, ad-hoc signing/Hardened Runtime, DMG, checksum, attestation, and publication gates. Those runs establish the baseline only; they do not establish exact macOS 26.6.2 execution or macOS 27 execution.

Post-remediation branch CI run [33961431631](https://github.com/erhansavas/Cuelixa/actions/runs/33961431631) completed successfully on the arm64 `macos-26` runner: the log records macOS 26.6.2 (25G83), Xcode 26.6 (17F113), Swift 6.3.3, and the MacOSX26.5 SDK. The source manifest, smoke checks, 22 Swift Testing tests, two XCTest performance tests, one UI launch test, Debug/Release builds, and Analyze all passed. The validator intentionally skips its generated local AVPlayer runtime smoke in CI compatibility mode, and no Icon Composer appearance rendering was performed; macOS 27 and the six requested icon appearances therefore remain open.

## Rejected ideas

- Enabling App Sandbox, adding notarization, or removing legacy `~/podcast` support: the repository documents these as deliberate distribution/migration decisions; no new defect evidence justifies the added entitlement/bookmark architecture or paid signing dependency.
- Treating the legacy raster icon as intrinsically broken: Apple documents automatic adaptation and permits flattened icons. Actual border/visibility failure cannot be claimed without native rendering.
- Restoring the foreground-only launch assertion: PR #6 and the existing UI behavior establish that the nonactivating overlay can leave the process in the background by design.
- Rewriting `SubtitleBalancer`, adding arbitrary cue limits, or changing SRT parsing for FIFOs: complexity/performance concerns were not backed by a supported-runtime measurement or a deterministic production failure, so they remain Needs Confirmation.
- Fixing the periodic playback observer’s possible post-await generation race: static review did not produce a deterministic stale-session outcome, and the other callback paths already guard their generation; it remains unverified.
- Broad dead-code/dependency cleanup: duplicate helpers and compatibility entry points were not shown to cause a defect and removal would expand scope without measurable user value.
- Calling the `actions/attest` advisory a High Cuelixa vulnerability: the exact workflow input and bundled `nobrace` path falsify exploitability for the reviewed release route; the finding is Low supply-chain hygiene.

## Verification and self-review certification

Every finding in the table has a precise baseline claim, direct repository/API evidence, an active falsification check, and a smallest-scope remediation. Each applied code change was challenged for root-cause coverage, race/error behavior, compatibility with Cuelixa’s documented local-first purpose, and unnecessary complexity. Focused regression tests were added only for the three verified filesystem paths; no mirror tests were added for the action pin or icon metadata.

Local checks completed on this host: `git diff --check`, `./Scripts/verify-source-manifest.sh`, and JSON parsing of the Icon Composer document. Native Swift/Xcode build and test execution is not available on this Linux host; branch CI independently compiled, tested, and analyzed the project on macOS 26.6.2. The icon’s source integration is verified in the repository, while macOS 27 and six-appearance visual rendering remain open items above. No item that failed or lacked the Verification Mandate is presented as a verified final finding.
